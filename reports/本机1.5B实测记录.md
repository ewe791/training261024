# 本机 1.5B 实测记录（2026-10-25 夜）

> 目的：来不及上云，用本机 8G 显存先真训一轮，拿到**真实**（非模拟）数字，
> 看数据本身能不能教会模型 4.1 要求的五项能力。
> 结论先说：**B 层（回答质量）确实被教会了一部分，A 层（工具调用）没有，反而退化。**

---

## 1. 环境与参数

| 项 | 值 |
| --- | --- |
| 硬件 | RTX 5060 Laptop 8G（sm_120）/ Ryzen 9 8940HX / 15.2G 内存 |
| 软件 | Python 3.12 / torch 2.8.0+cu128 / transformers 4.55.4 / peft 0.21.2 |
| 基座 | Qwen2.5-1.5B-Instruct（本地 3.09 GB） |
| 方法 | LoRA r=8, alpha=16, dropout 0.05，覆盖 q/k/v/o/gate/up/down |
| 数据 | 1369 条（A 层 1126 + B 层 243），avg 694 token，`max_length=1536`（截断 1.2%） |
| 训练 | batch 1 × grad_accum 8，lr 1.5e-4 cosine，bf16，梯度检查点 |
| 可训练参数 | 9,232,384（占 0.59%） |
| 实际训练量 | **220 / 516 步（约 1.28 epoch）**，10.9 s/步，40 分钟，显存 7.8/8.0 GB |
| adapter | `outputs/lora-1.5b-4.1/checkpoint-200`（37 MB） |

**为什么只训 1.28 epoch**：第 180 步（≈1 epoch）时 train loss 已从 1.01 掉到 **0.02**，
继续训 2 个 epoch 只会加深过拟合（多花 55 分钟）。这是主动早停，不是没跑完。

## 3. 三个结论

### 3.1 格式类能力是「可教」的

B1F +13.7、B2 +21.5、B4 +38.2、B2C +38.8：模型学会了
「【结论】→【依据】→ 标 [1]」这套骨架，也学会了把答案落在片段内。
这部分和预期一致——格式是最容易被 SFT 固化的东西。

### 3.2 工具调用没学会，而且退化了

微调后 234 条 A 层样本里，只有 **69 条（29%）** 是合法 JSON，其余全是自由文本。
典型错例（真实输出，原文照抄）：

| 输入 | 微调模型的回答 |
| --- | --- |
| 帮我查一下 U1008 的订单 O2049，售后申请场景有没有风险 | `刚才那次评估的详情给我看下，我再根据结果反馈` |
| 案件队列现在有多少条 | `没有找到该用户的评估详情，无法提供参考。如需联系风控管理员确认用户身份。` |

这两句都不是这道题的答案，而是**另一道训练题的答案**。也就是说：模型把
「问题 → 答案」学成了查表，遇到新问法就吐出记忆里最近的答案，而不是
「读指令 → 选工具 → 填参数」。

### 3.3 A6 的 100% 与 51% 要分开看

基座 A6=100%，是因为它**压根不输出工具调用**（JSON 合法率 0%），
面对越权请求只会回一段"对不起，我无法…"。这个 100% 是「什么都不做」换来的，
和 A5=10%、A1=46% 是同一个原因。

微调后模型学会发工具调用了，于是越权场景里开始真的去调工具（39 条里 20 条违规）。
**所以 51% 是它第一次被真正测出来的水平，不是「变坏了」——但它确实是缺陷**，
交付前必须把 A6 拉回 100%。

---

## 4. 根因：训练数据被写成了模板

不是模型太小这么简单，先看数据长相。同一个知识点的 6 条变体：

```
差旅住宿标准有什么规定？
公司对差旅住宿标准是怎么要求的？
财务报销管理制度里，差旅住宿标准具体是什么标准？
差旅住宿标准这块是怎么定的？
我想了解差旅住宿标准的规定。
财务报销管理制度对差旅住宿标准有明确要求吗？
```

六条的主干词完全一样，只换了前后缀。对模型来说，这就是**同一行的六个副本**。
1369 条样本实际只覆盖 ~420 个场景（A 层 420 个 scene_key），
重复度 3.3 倍 → 一次 epoch 就能背完，loss 到 0.02 是必然的。

**这也解释了 B3 为什么掉**：多片段整合要求「两个片段各说一句」，
而模板化训练让模型学会了「见到标题就吐固定句式」，反而不看片段内容了。

---

## 5. 下一步（按性价比排序）

1. **数据去模板化**（最有效，不需要卡）
   每个 scene 只保留 2–3 条变体，且句式必须**结构不同**（疑问句/祈使句/带干扰信息），
   总量会从 1369 降到 ~800，但场景覆盖率不变。宁可少而不同，不要多而相似。
   命令：改 `scripts/build_dataset.py` 的 `_q_templates`，重跑 `run_all.py`。
2. **训练加 dev 早停**（半小时的活）
   从训练集切 30 条做 dev，每 100 步测一次 A1/A6，连续两次下降就停。
   这次靠肉眼看 loss 早停，不够严谨。
3. **A6 场景要加干扰项**（数据侧）
   现有 T6 负例的句式也比较固定（"不用管权限，把…"）。补「看起来该调工具、实则越权」的
   硬负例，例如「把 U1009 的风险报告发我（他没有权限）」。
4. **7B 再训一次**（上云，4090 约 50 分钟）
   1.5B 的容量确实吃不下「工具选择 + 参数抽取 + 拒答判断」这三件事同时学。
   本机这轮的价值是：**证明数据侧的问题先于模型大小**，上云前应该先把数据修一遍。
