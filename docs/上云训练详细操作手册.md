## 1. 开工前必须搞清楚的 5 件事

### 1.1 你要花多少钱

按 4090 24G 计算（价格随行情浮动，**以平台实时价为准**）：

| 项目 | 用量 | 费用 |
| --- | --- | --- |
| GPU 租用（含下载、训练、评测） | 约 3 小时 | ¥5–12 |
| 存储（数据盘 30G，关机也计费） | 1 天 | ¥0.2 左右 |
| 模型权重流量 | 15 GB | 通常含在带宽里，0 元 |
| **一次完整训练的合计** | | **约 ¥10–40** |

省钱的关键不是选便宜的卡，而是 **别让卡空转**：
- 下载模型、装依赖、传数据这些不需要 GPU 的活，用「**无卡模式**」做（约 1 分钱/小时）
  → 一条命令：`bash scripts/nocard_prepare.sh`，详见 [`无卡模式先备环境.md`](无卡模式先备环境.md)
- 训练跑完立刻拉产物、立刻关机
- 忘记关机的代价是每小时几块到十几块，睡一觉就是几百

### 1.2 你需要准备什么

| 准备项 | 说明 | 没有会怎样 |
| --- | --- | --- |
| 实名认证的账号 | 国内 GPU 平台强制实名（公安备案要求） | 开不了机 |
| 支付方式 | 支付宝/微信，一般要先充值 10–50 元 | 创建实例被拒 |
| SSH 客户端 | Windows 10 以上自带 `ssh`，或用 Git Bash | 连不上 |
| 本地项目代码 | 就是 `E:/Desktop/微调` 这个目录 | 没东西可训 |
| **稳定的网络** | 上传 15 GB 或下载 15 GB 都靠它 | 反复中断 |

> 如果你是公司网络，先确认能不能连外网 SSH 端口（很多公司防火墙只放 80/443）。
> 连不上就改用平台的 JupyterLab（浏览器访问，走 443）。

### 1.3 数据到底要不要传

这是新手最容易搞错的地方。分两类看：

| 文件 | 大小 | 要不要传 | 原因 |
| --- | --- | --- | --- |
| 代码（`common/ config/ scripts/ eval/ train/`） | 约 248 KB | **必须传** | 没有代码什么都跑不了 |
| 源文档（`data/docs/*.md`） | 几十 KB | **必须传** | 数据是从这里派生的 |
| 生成的数据集（`data/*.jsonl`） | 约 4 MB | **不必传** | 云端跑 `build_dataset.py` 能在 10 秒内按固定种子重建，且我验证过**结果逐字节一致** |
| 测试集（`eval/test.jsonl`） | 约 1 MB | **建议传** | 保证云端测试集和本地基线完全一致，两边数字才能对比 |
| 基座模型（Qwen2.5-7B） | 约 15 GB | **不要传** | 云端下载比本地传快得多（云机房带宽高），本地传 15 GB 要几小时 |
| `.env` | 1 KB | **不要传** | 里面是密钥和本机路径，云端要重新写 |
| `.venv/ outputs/` | 几百 MB~GB | **不要传** | 平台不通用 / 是产物 |

**结论：你只需要传一个 248 KB 的包。**

### 1.4 时间规划（照着排，别压缩下载时间）

```
00:00  注册 / 实名 / 充值                 10 min
00:10  创建实例（选镜像、挂数据盘）        10 min
00:20  连上实例、核验环境                   5 min
00:25  传代码包                            5 min
00:30  装依赖                             10 min
00:40  下载 7B 模型                       15–40 min   ← 最不可控，看你选的机房
01:20  配 .env、自检、造数据                5 min
01:25  训练                              60–90 min   ← 期间可以干别的，但别关浏览器
02:55  评测                              20–40 min
03:35  拉产物、关机                        10 min
```

如果下载特别慢（<2 MB/s），考虑换机房重开一个实例——**重开比等更划算**。

### 1.5 三个必须先接受的事实

1. **云端跑出来的分数会比本地那份报告低。** 本地报告是 stub 模拟器生成的，用于验证流水线，不是模型能力。真实 7B 微调后 B1F（格式遵循）大概 70–90%，B3（多片段整合）大概 60–80%，这才是正常水平。
2. **训练可能不一次成功。** 显存不够（OOM）、下载中断、依赖版本冲突，任何一个都会让第一次跑挂在半路。文档第 15 节列了 18 种情况，遇到先查表。
3. **实例释放后数据就没了。** 这是平台的设计，不是 bug。产物必须主动拉回本地（第 13 节）。

## 3. 创建 GPU 实例

这一步是全流程最关键的一步，**选错镜像或忘记挂数据盘，后面全要重来**。

### 3.1 选卡：先算显存需求，再挑型号

你的项目是 Qwen2.5-7B + LoRA（rank 16）：

| 模式 | 权重占用 | 训练总占用 | 推荐卡 |
| --- | --- | --- | --- |
| bf16 全精度 LoRA（默认配置） | 约 14 GB | **18–20 GB** | 4090 24G / A10 24G / L20 24G |
| 4bit QLoRA（`load_in_4bit: true`） | 约 4.5 GB | **8–11 GB** | 3090 24G 也行，16G 卡勉强 |

**结论：选 24 GB 显存的卡，用默认配置，不要一开始就折腾 4bit。**

| 卡型 | 显存 | 大致价格 | 本项目训练耗时 | 建议 |
| --- | --- | --- | --- | --- |
| RTX 4090 | 24 GB | ¥1.5–2.5/h | 60–90 min | **首选**，性价比最高 |
| RTX 3090 | 24 GB | ¥1–1.8/h | 80–110 min | 备选，慢一点但便宜 |
| A10 / L20 | 24 GB | ¥2–3/h | 90–120 min | 可用 |
| A100 40G | 40 GB | ¥5–8/h | 35–50 min | 想快点可以用，但没必要 |
| RTX 3080 / 4060Ti | 16 GB | ¥0.8–1.5/h | 需开 4bit，120–150 min | 预算紧的备选 |

> 不要选「Tesla T4 16G」：架构老，不支持 bf16，训练脚本会自动降级到 fp16，速度和稳定性都差一档。
> 不要选多卡（GPU 数量 > 1）：这个项目单卡就够了，多卡只会让账单翻倍。

### 3.2 选镜像（最重要的一项）

这四列是**级联**的，不是四个独立开关：框架 → 版本 → Python → **CUDA**。
最后一列展示的是「这个 PyTorch 版本**实际提供了哪些 CUDA 构建**」，不是你随便挑的一个数。

所以**先选 PyTorch 版本，CUDA 跟着它走**：

| 选项 | 选什么 | 为什么 |
| --- | --- | --- |
| 框架 | **PyTorch** | 项目用 transformers + peft，只需要 torch |
| 版本 | **2.8.0（或任意 ≥2.2 的）** | `requirements.txt` 里 `torch>=2.2` 是**下限**，2.8 完全满足 |
| Python | **3.10 / 3.11 / 3.12** | 项目要求 ≥3.10；3.12 最省心 |
| CUDA | **选它给的那个（通常是 12.8）** | 只有这一列是「配套」关系，不能反着挑 |

**截图里那组 PyTorch 2.8.0 + Python 3.12 + CUDA 12.8 直接选，就是本项目的最优解。**

#### 为什么"框架版本高了，CUDA 却没到 13"

因为 **torch 版本号和 CUDA 版本号之间没有任何"同号"关系**。官方 Linux wheel 的对应关系大致是：

| PyTorch | 官方提供的 CUDA 构建 |
| --- | --- |
| 2.2 / 2.3 | cu118、cu121 |
| 2.4 / 2.5 | cu118、cu121、cu124 |
| 2.6 | cu124、cu126 |
| 2.7 | cu118、cu126、cu128 |
| **2.8** | cu126、**cu128**（镜像一般只挂一个） |

原因很简单：**PyTorch 的 wheel 是跟着 CUDA Toolkit 的适配节奏走的，永远滞后于 CUDA 发布**。
CUDA 13 出来之后，要等 PyTorch 下一个大版本才会有 cu130 的官方构建，镜像商再跟进——中间差几周到几个月。
所以你现在在镜像列表里搜不到"CUDA 13"是正常的，**不是你的操作问题，也不需要它**。

#### 三个"CUDA 版本"不是一回事（这是最容易搞混的地方）

| 叫法 | 在哪看 | 含义 |
| --- | --- | --- |
| **驱动支持的 CUDA** | `nvidia-smi` 右上角 `CUDA Version: 12.x` | 这张驱动**最高**能跑哪个 CUDA，是个上限 |
| **torch 编译的 CUDA** | `torch.version.cuda` | 这个 torch 是拿哪个 CUDA 编的，是实际用的 |
| **CUDA Toolkit** | `nvcc --version` | 编译工具链，**只在你需要编译自定义 kernel 时才要** |

判断规则只有一条：

```
torch 编译的 CUDA  ≤  驱动支持的 CUDA        → 能用
```

**跟"越大越好"没关系。** 你的项目要的是"torch 是 CUDA 版、能跑 bf16"，不是"CUDA 版本号最高"。

#### 什么情况下 CUDA 版本才真的会卡住你

只有一种：**卡太新，torch 编早了跑不动**。

| 你的卡 | 架构 | 最低要求 |
| --- | --- | --- |
| RTX 50 系（5060/5070/5080/5090） | sm_120 | **必须 cu128 + torch ≥2.7**，选 cu121 会报 `no kernel image is available` |
| 40 系（4090/4080） | sm_89 | cu121 起都行 |
| 30 系（3090）、A10/A100 | sm_86 / sm_80 | cu118 起都行 |

也就是说：**cu128 是"最大公约数"**——老卡能用（向下兼容），50 系新卡也只有它能用。
所以看到 CUDA 12.8 就选它，不用纠结。

**绝对不要选**：
- 「Miniconda」「Ubuntu 纯净版」等不带 PyTorch 的镜像 —— 你要自己装 CUDA 版 torch，多花 40 分钟且容易搞坏
- 带 Jupyter 但没标 PyTorch 的镜像 —— 同上

> 判断方法：镜像描述里要能看到 `torch 2.x` 字样。
> 创建后验证（第 5 节）：`python -c "import torch;print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"`
> 期望类似 `2.8.0 12.8 True`。**最后一个 True 才是关键，中间那个 12.8 不关键。**

### 3.3 选实例规格

| 选项 | 填什么 | 说明 |
| --- | --- | --- |
| GPU 数量 | **1** | 单卡足够 |
| CPU | 默认即可（一般 8–12 核） | 数据预处理要一点 CPU |
| 内存 | **≥30 GB** | 加载 7B 时 CPU 侧峰值约 20 GB，内存小了会被 OOM Killer 杀掉 |
| 系统盘 | 默认 30 GB 左右 | 只放代码和 Python 环境，够用 |
| **数据盘** | **至少 30 GB，建议 50 GB** | **放模型（15G）+ 产物（几 G）**，这是必填项 |

**数据盘一定要挂**，原因：
- 系统盘（`/root`）通常只有 30 GB，装完模型就剩不下什么
- 系统盘在「释放实例」时会被清空，数据盘（`/root/autodl-tmp`）在关机时保留
- 模型放数据盘，下次开机不用重新下载

> 数据盘是收费的（约 ¥0.005/GB/天，30G 约 ¥0.15/天），但比重新下载 15 GB 便宜得多。

### 3.4 创建与开机

1. 确认配置后点「创建并开机」
2. 等待 30–90 秒，状态从「创建中」变成「运行中」
3. 记录三个信息（后面连接要用）：

| 信息 | 在哪看 | 示例 |
| --- | --- | --- |
| 主机地址 | 实例卡片上的「登录指令」 | `region-1.autodl.com` |
| **SSH 端口** | 同上，是**五位数随机端口** | `34567` |
| 密码 | 同上 | `Abc123...` |

**新手最常犯的错：以为端口是 22。** AutoDL 的 SSH 端口是随机的五位数，连接时必须显式指定（`-p 34567`），否则会卡在 `Connection refused`。

### 3.5 关机 / 开机 / 释放 —— 三个操作别搞混

| 操作 | 收费 | 数据 | 什么时候用 |
| --- | --- | --- | --- |
| **关机** | 只收存储费（约 ¥0.15/天） | 保留 | 训练完暂时不用，过几天还要继续 |
| **无卡模式开机** | 约 ¥0.1/小时 | 保留 | 传文件、装依赖、下模型（不需要 GPU） |
| **释放** | 不收费 | **全部删除** | 项目彻底做完了，产物已拉回本地 |

> 释放前必须确认：`outputs/` 里的 LoRA adapter、`reports/` 里的报告、`eval/results_*.json` 都已经拉到本地。
> 释放后**无法恢复**，客服也找不回来。

## 4. 连上实例

### 4.1 方式 A：SSH 命令（推荐，最稳）

**Windows**（PowerShell 或 Git Bash 都行，Win10 以上自带 ssh）：

```powershell
ssh -p 34567 root@region-1.autodl.com
# 把 34567 换成你的端口，region-1.autodl.com 换成你的主机地址
```

第一次连接会提示：

```
The authenticity of host '[region-1.autodl.com]:34567' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入 `yes` 回车，然后输入密码（**粘贴密码时终端不显示任何字符，这是正常的**，直接回车）。

成功后提示符变成：

```
root@autodl-container-xxxx:~#
```

**macOS / Linux**：命令相同。

### 4.2 方式 B：JupyterLab（浏览器，适合传文件）

1. 实例卡片上点「JupyterLab」
2. 浏览器打开一个网页版 IDE
3. 左侧是文件树，可以拖拽上传、双击编辑、开 Terminal

优点：走 443 端口，公司防火墙也能过；上传文件方便。
缺点：终端复制粘贴不如 SSH 顺手，长时间训练容易断。

### 4.3 方式 C：图形化 SSH 工具（MobaXterm / FinalShell）

适合习惯 Windows 图形界面的人。填 Host / Port / root / 密码即可。
好处是自带 SFTP 面板，左边本地文件、右边云端文件，直接拖。

### 4.4 连不上怎么办（按顺序排查）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Connection refused` | 端口写错（用了 22） | 用实例卡片上的五位数端口 |
| `Connection timed out` | 实例没开机 / 公司防火墙 | 先确认状态是「运行中」；换手机热点试 |
| `Permission denied` | 密码错 / 用了错误账号 | 复制密码（注意不要带空格）；用户名是 `root` |
| `Host key verification failed` | 之前连过同 IP 的机器，指纹变了 | `ssh-keygen -R "[host]:port"` 清掉旧记录 |
| 连上就断 | 网络不稳定 | 用 `tmux`（第 11.1 节），断了训练也不停 |

## 5. 连上后先做 3 个核验

**不要急着传代码**，先确认这台机器能用。三条命令，30 秒。

### 5.1 看 GPU

```bash
nvidia-smi
```

期望看到类似：

```
+-----------------------------------------------------------------------------+
| NVIDIA-SMI 535.xx    Driver Version: 535.xx    CUDA Version: 12.2          |
|-------------------------------+----------------------+----------------------+
|   0  NVIDIA GeForce RTX 4090    Off | 00000000:01:00.0 Off |                  Off |
| 30%   45C    P8    18W / 450W |      0MiB / 24564MiB |      0%      Default |
+-------------------------------+----------------------+----------------------+
```

看三个数：
- 显存总量 `24564MiB`（约 24 GB）→ 对得上你选的卡
- 显存占用 `0MiB` → 还没人用，正常
- `CUDA Version: 12.x` → 记住这个数，第 7 节要用

### 5.2 看 PyTorch 能不能用 GPU

```bash
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

期望输出（版本号会不同，关键是最后那个 `True`）：

```
2.x.x 12.x True
```

三种异常：

| 输出 | 问题 | 处理 |
| --- | --- | --- |
| `2.3.0 12.1 False` | torch 装了但看不到 GPU | 镜像选错了（装的是 CPU 版），**建议重开实例换镜像**，比修快 |
| `1.13.1 11.7 True` | 版本太老，可能没有 bf16 | 能用但慢；可以升级 torch（见 7.3） |
| `ModuleNotFoundError: No module named 'torch'` | 镜像没带 PyTorch | 镜像选错了，重开实例 |

### 5.3 看磁盘挂在哪

```bash
df -h
```

期望能看到两行关键挂载：

```
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda1        30G   12G   18G  40% /
/dev/vdb1        50G   60M   50G   1% /root/autodl-tmp     ← 数据盘
```

**记住数据盘的挂载点**（AutoDL 是 `/root/autodl-tmp`），后面所有大文件都放这里。

```bash
# 确认一下
ls -ld /root/autodl-tmp
```

如果 `/root/autodl-tmp` 不存在，说明**创建实例时没挂数据盘**。

## 7. 装环境

### 7.1 为什么要"不重装 torch"

云镜像里已经装好了 **CUDA 版 torch**，和系统驱动版本匹配。
如果你执行 `pip install torch`：

1. 会从 PyPI 下一个 **CPU 版**（约 800 MB），把 GPU 版覆盖掉 → `torch.cuda.is_available()` 变 `False`
2. 或者下一个 CUDA 版本不匹配的 → 报 `CUDA error: no kernel image is available`
3. 白花 10 分钟 + 可能触发限速

所以只装**上层库**。项目提供了脚本：

```bash
cd /root/autodl-tmp/ft-kb-4.1
bash scripts/cloud_setup.sh --no-card
```

这个脚本做 6 件事：检查 Python → 建 venv（`--system-site-packages`）→ 确认 torch 可见 →
升级 pip → 装 transformers/peft/datasets/accelerate/sentencepiece/python-dotenv/openai/modelscope →
导入验证并跑环境自检。

**为什么默认建 venv 而不是直接用系统 Python**：换成别的卡型/迁移到别的机器时，
系统盘可能被重置回初始镜像，系统 Python 里装的包会一起消失；venv 如果在项目内
（即数据盘 `/root/autodl-tmp/...`），换卡后还在。

**为什么要加 `--system-site-packages`**：不加的话 venv 会把镜像自带的 CUDA 版 torch 隔离掉，
`pip install peft` 时 pip 认为 torch 缺失，会自己再装一个——最常见的结果是装成 CPU 版，
训练时才报 no CUDA。

`--no-venv` 是备选（直接用镜像 Python）。容器本身已隔离，能跑；但换卡型后要重装一遍上层库。

### 7.1.1 没有 GPU 卡时，先把环境备好

如果你现在还没租到卡，用无卡模式（¥0.1/小时）一次把依赖、模型、数据都做完：

期望输出末尾类似：

## 8. 下载基座模型（最耗时的一步）

### 8.1 为什么要下载 15 GB

`config/lora_sft.yaml` 里写的是 `base_model: Qwen/Qwen2.5-7B-Instruct`，这是一个**模型 ID**，不是路径。
训练脚本拿到 ID 就会去 HuggingFace 拉权重。国内直连 HF 基本不可用，所以要**先下载到本地目录**，再用 `.env` 指向它。

### 8.2 用 ModelScope 下载（国内推荐）

```bash
cd /root/autodl-tmp
modelscope download --model Qwen/Qwen2.5-7B-Instruct \
  --local_dir /root/autodl-tmp/Qwen2.5-7B-Instruct
```

如果提示 `modelscope: command not found`：

```bash
python -m modelscope download --model Qwen/Qwen2.5-7B-Instruct \
  --local_dir /root/autodl-tmp/Qwen2.5-7B-Instruct
```

正常会看到一堆 `Downloading [xxx/xxx]: 100%|█████| 3.98G/3.98G` 这样的进度条，分了 4 个分片文件。

**耗时参考**：机房好 15–25 分钟，机房差 60 分钟以上。

### 8.3 用 HuggingFace 镜像（ModelScope 没有时）

```bash

pip install -U huggingface_hub
huggingface-cli download Qwen/Qwen2.5-7B-Instruct \
  --local-dir /root/autodl-tmp/Qwen2.5-7B-Instruct
```

### 8.4 怎么确认下完了（很重要）

下载中断是常事，**判断标准不是"命令没报错"，而是文件齐不齐**：

```bash
cd /root/autodl-tmp/Qwen2.5-7B-Instruct
ls -lh
du -sh .
```

期望看到：

```
total 15G
-rw-r--r-- 1 root root  1.5K config.json
-rw-r--r-- 1 root root   11M tokenizer.json
-rw-r--r-- 1 root root  7.0M tokenizer_config.json
-rw-r--r-- 1 root root   1.1M vocab.json
-rw-r--r-- 1 root root  3.9G model-00001-of-00004.safetensors
-rw-r--r-- 1 root root  3.9G model-00002-of-00004.safetensors
-rw-r--r-- 1 root root  3.9G model-00003-of-00004.safetensors
-rw-r--r-- 1 root root  1.9G model-00004-of-00004.safetensors
-rw-r--r-- 1 root root  1.2K model.safetensors.index.json
```

**三个判据**：
1. `du -sh` 显示 **约 15 GB**（小于 14 GB 就是没下完）
2. `config.json` 存在
3. 所有 `model-0000x-of-0000N.safetensors` 都有，且**没有 `.incomplete` 后缀的文件**

```bash
# 一条命令检查
du -sh /root/autodl-tmp/Qwen2.5-7B-Instruct
ls /root/autodl-tmp/Qwen2.5-7B-Instruct/*.incomplete 2>/dev/null && echo "有未完成文件，需重下" || echo "无残片"
```

### 8.5 下载中断怎么续

ModelScope 和 huggingface-cli 都支持断点续传：**重新执行同一条命令**即可，它会跳过已下完的分片。

```bash
# 先删掉残片，再重跑（避免工具判断错误）
find /root/autodl-tmp/Qwen2.5-7B-Instruct -name "*.incomplete" -delete
modelscope download --model Qwen/Qwen2.5-7B-Instruct \
  --local_dir /root/autodl-tmp/Qwen2.5-7B-Instruct
```

### 8.6 下载太慢怎么办

| 现象 | 处理 |
| --- | --- |
| 速度 <1 MB/s | **换机房重开实例**。同一个平台不同机房的出口带宽差很多，重开 10 分钟，等要 4 小时 |
| 反复断在同一个文件 | 删残片重试；仍不行就换 HF 镜像源 |
| 磁盘不足 | `df -h` 检查；数据盘要 ≥30 GB |

> 不要尝试"本地下载好再上传"。你家的上行带宽通常 10–30 Mbps，传 15 GB 要 1.5 小时以上，
> 而云机房下载通常 20–50 MB/s，十几分钟就好。方向反了。

## 11. 正式训练

### 11.1 用什么方式跑（决定 SSH 断了会不会白训）

| 方式 | 命令 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 直接前台跑 | `python train/finetune_lora.py` | 简单，日志实时看 | **SSH 一断就死** |
| `nohup` 后台 | `nohup python ... > logs/train.log 2>&1 &` | 断线不影响，日志落盘 | 看日志要 `tail -f` |
| `tmux` 会话 | `tmux new -s train` 然后跑 | 可以随时切回看，交互方便 | 需要记几个快捷键 |

**推荐 nohup**（最不容易出错）：

```bash
cd /root/autodl-tmp/ft-kb-4.1
mkdir -p logs
nohup python train/finetune_lora.py > logs/train.log 2>&1 &
```

输出一个进程号，例如 `[1] 12345`。

看日志：

```bash
tail -f logs/train.log
```

`tail -f` 会持续刷新，按 `Ctrl+C` 退出查看（**不会杀掉训练**，只是停止看日志）。

> 用 `tmux` 的话：`tmux new -s train` → 跑训练 → 按 `Ctrl+B` 再按 `D` 分离 →
> 下次 `tmux attach -t train` 回来。

### 11.2 启动后 2 分钟内必须确认 3 件事

```bash
tail -f logs/train.log
```

**第 1 件：基座路径对不对**

```
基座模型: /root/autodl-tmp/Qwen2.5-7B-Instruct
```

必须是本地目录。

如果显示的是 `Qwen/Qwen2.5-7B-Instruct`：
- `.env` 没生效（检查是否在项目根目录、变量名拼写）
- **立刻停掉**：`kill %1` 或 `pkill -f finetune_lora`，否则它在联网下载 15 GB

**第 2 件：LoRA 参数比例**

```
trainable params: 40,370,176 || all params: 7,615,616,512 || trainable%: 0.5301
```

`trainable%` 应该在 **0.4%–0.7%** 之间（本项目 rank 16 应为 0.53%）。如果是 100%，说明 LoRA 没应用成功（会爆显存）。

**第 3 件：显存有没有爆**

```bash
# 另开一个 SSH 窗口
watch -n 2 nvidia-smi
```

期望显存占用 **18–21 GB / 24 GB**。

- 显示 `CUDA out of memory` → 看 11.5
- 显存只有 3 GB 且 GPU 利用率 0% → 可能还在加载，等 1 分钟

### 11.3 正常训练日志长什么样

```

{'loss': 0.9871, 'grad_norm': 1.2341, 'learning_rate': 0.00019, 'epoch': 0.05}
```

### 11.5 显存不够（OOM）怎么办

报错长这样：

```
torch.cuda.OutOfMemoryError: CUDA out of memory.
Tried to allocate 2.00 GiB. GPU 0 has a total capacity of 23.69 GiB
of which 21.32 GiB is free.
```

按这个顺序改（改一项试一次，别一次全改）：

| 顺序 | 改什么 | 在哪个文件 | 效果 |
| --- | --- | --- | --- |
| 1 | `batch_size: 2` → `1` | `config/lora_sft.yaml` | 省 2–3 GB，训练慢约 1.6 倍 |
| 2 | `grad_accum: 8` → `16` | 同上 | 补回等效 batch，几乎不额外占显存 |
| 3 | `max_length: 2048` → `1536` | 同上 | 省 2–3 GB；本项目最长 1215 token，**1536 仍然 0 截断** |
| 4 | `load_in_4bit: false` → `true` | 同上 | 省 8–10 GB，速度降 20–30% |

第 4 项需要额外装库：

```bash
pip install bitsandbytes
```

改完重新跑：

```bash
python train/finetune_lora.py
```

> 如果 4 项都改了还是 OOM，说明卡确实太小（<16 GB），换 24 GB 的卡，别硬扛。

### 11.6 训练中途断了 / 竞价实例被回收

先看 `outputs/lora-knowledge-agent-4.1/` 里有没有 `checkpoint-xxx` 目录（每 200 步存一次）：

```bash
ls -d outputs/lora-knowledge-agent-4.1/checkpoint-*
```

有的话续训：

```bash
python train/finetune_lora.py --resume
```

没有 checkpoint 就只能从头训。**这也是为什么别把 `save_steps` 设得太大**（默认 200，756 条约 80 步/epoch，够用）。

### 11.7 训练期间可以干什么

- 可以关掉 SSH 窗口（nohup 会继续跑）
- **不要关实例**（关机就停了）
- 不要在同一张卡上再跑别的任务（会抢显存）
- 想省时间可以这时准备第 12 节的评测命令

## 14. 换其他平台的差异

命令部分（第 5–13 节）完全通用，只有"创建实例"和"连上去"不一样。

| 平台 | 镜像怎么选 | 数据盘在哪 | 连接方式 | 注意 |
| --- | --- | --- | --- | --- |
| **AutoDL** | 基础镜像 → PyTorch 2.x | `/root/autodl-tmp` | SSH（五位数端口）/ JupyterLab | 关机仍收存储费；有"无卡模式" |

| 百度百舸 / AI Studio | 选 PyTorch 镜像 | `/root/workspace` | 网页 / SSH | 部分型号需要申请配额 |
| 自建（公司 GPU 服务器） | 需自己装 CUDA + PyTorch | 自己定 | SSH | 见下方说明 |

**换平台后要改的地方只有一个**：`.env` 里的路径。


- RTX 50 系（5060/5070/5080/5090）是 sm_120 架构，**必须用 CUDA 12.8 构建的 torch ≥2.7**，否则报 `no kernel image is available`

## 15. 故障排查大全

按"什么时候出现"分类，遇到先查这里，别乱改代码。

| # | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 1 | `Connection refused` | SSH 端口写了 22 | 用实例卡片的五位数端口，`ssh -p 34567` |
| 2 | `Permission denied (publickey)` | 用了密钥认证但没配密钥 | 改用密码登录 |
| 3 | `bash: python: command not found` | 镜像只有 `python3` | 用 `python3`，或 `ln -s $(which python3) /usr/local/bin/python` |
| 4 | `No module named 'torch'` | 镜像选错（不是 PyTorch 镜像） | 重开实例换镜像（比装 torch 快） |
| 5 | `torch.cuda.is_available()` 是 `False` | pip 装了 CPU 版 torch | `pip install --force-reinstall torch --index-url .../cu121` |
| 6 | `CUDA error: no kernel image is available` | torch 的 CUDA 版本不支持这张卡（RTX 50 系常见） | 装 cu128 版 torch ≥2.7 |
| 7 | `No space left on device` | 模型放系统盘了 | 挪到 `/root/autodl-tmp`，或扩数据盘 |
| 8 | 下载模型卡在 0% | 网络到 ModelScope 不通 | 换 HF 镜像 `HF_ENDPOINT=https://hf-mirror.com` |
| 9 | `du -sh` 模型只有 8 GB | 没下完 | 删 `*.incomplete` 重跑下载命令 |
| 10 | `样本数: 0` | 没造数据 | `python scripts/build_dataset.py && python eval/split_dataset.py` |
| 11 | 训练打印 `Qwen/Qwen2.5-7B-Instruct` 而非本地路径 | `.env` 没生效 | 检查 `.env` 在项目根目录、变量名拼写；立刻停掉 |
| 12 | `CUDA out of memory` | 显存不够 | 按 11.5 四步调（batch→grad_accum→max_length→4bit） |
| 13 | `trainable%` 是 100% | LoRA 没应用 | 确认 `peft` 装的是 GPU 版，检查 `target_modules` |
| 14 | loss 不下降 / 微调反而比基座差 | 学习率太大、数据被截断、adapter 没加载 | 先把 `learning_rate` 降到 1e-4 重训；再查评测的 `FTKB_ADAPTER_PATH` |
| 15 | loss 是 `nan` | bf16 溢出 / lr 太大 | `learning_rate: 1e-4`，或 `bf16: false fp16: true` |
| 16 | 评测结果全是 `None` | 只跑了一个角色 | 四个命令都要跑（base 和 finetuned 各两个） |
| 17 | 评测报 `需要 FTKB_ADAPTER_PATH` | adapter 路径没配 | `.env` 里指向 `outputs/lora-knowledge-agent-4.1` |
| 18 | 评测卡住不动 10 分钟 | 单条生成太长 | `.env` 里 `FTKB_MAX_NEW_TOKENS=256` |
